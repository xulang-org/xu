# Xu 借用与可变标记定稿：只读默认、隐式共享重借用与 `$` 统一标记

日期：2026-10-28。状态：**语言方向与新拼写已拍板；本文仍待 spec 批准，不是已实现的语言行为**。

证据基线：`xulang-org/xu`，分支 `cursor/spec-borrow-mut-coercion`，HEAD 与 `origin/dev` 均为 `2bd77e7`。本文只提出设计，不修改编译器、格式化器或自举源码。批准本 spec 前不写实现。

已拍板方向：**声明与使用都降低心智**——只读默认可省略，可变才标；`$` 是「可变」统一标记；使用者只记 `$name`（绑定）与 `$&`（可写借用）。** 可变绑定写 `$x := ...`（**否决**旧稿 `&$x :=`）；可写借用在表达式位写 `$&x`、类型位写 `$&T`；重借用默认省略（写 `r`），显式穿过写 `&*r`（期望区分读写；否决 `$&*r` / `*$&r`）。表达式位的只读借用默认省略，传参 / receiver 自动只读借；兼容期保留可选 `&x` 并逐步弱化其教学与规范示例地位。类型位建议仍保留 `&T`，区分借用与拥有值，不额外标只读。场景全表见 **§0**；推进顺序按场景对齐为 **A 诊断 → B 隐式 `&mut T → &T` 降级 → C 新拼写并存与自动迁移 → 旧拼写弃用**；每阶段 Gen2 == Gen3 必过，批准 spec 前不实现。`mut_ref` / `mut_loan` 仅保留备选对比，不推荐；`~` 方案已否决。

### 0.5 使用：重借用（心智优先：少写、复用已有符号）

目标：读代码的人不必先学会第三种可变拼写。

**使用者只记两句：**

1. **只要读**（已有引用 `r`，要 `&T`）→ **写 `r`**。
2. **要显式再借一次 pointee** → **写 `&*r`**（今日已有）。只读 / 可写由期望决定：`&T` → 共享；`$&T` → 独占。同步传给 `$&T` 形参仍直接写 `r`（E21a）。

**否决 `$&*r` 与 `*$&r`：** 二者都是新串。`$&*r` 符号最长；`*$&r` 按现有组合读成 `*($&r)`（先借槽再解引用），不是独占子借，更耗心智。`$&` 只用于从 place 取可写借用（D17）；重借复用 `&*`。

| # | 意图 | 今日 | 目标 | 动手 |
| --- | --- | --- | --- | --- |
| E19 | 只读，手里 `&T` | `&*r` | **`r`**；`&*r` 兼容 | 省略 |
| E20 | 只读，手里独占 | `&*r` | **`r`**（B）；`&*r` 兼容 | 省略 |
| E21a | 可写同步传参 | 自动 | **`r`** | 省略 |
| E21b | 显式独占子 loan | `mut &*r` | **`&*r`**（期望 `$&T`） | 显式用 `&*` |
| E22 | 共享→独占 | 拒绝 | 从 owner 重新 `$&` | 诊断 |
| E23 | 借引用槽 | `&r` | 同；≠ `&*r` | 少见 |
| E24 | 非 Ident | 受限 | 先绑局部 | 不绕过 |

**冻结一句：** 只读 view 活着时，不能经父引用再写 / 再开独占子借。

**分界：** 拥有值上第一次可写借 → `$&x`；已有引用再借 → 省略或 `&*r`。

### 0.8 由场景推出的统一规划

1. **心智三句**（覆盖 A–G）：只读可省；可变绑定 `$name`；可写借用 `$&`。声明标一次（A2/A4/A6/A8），使用不重标（B9–B11）。
2. **正交**：左 `$` = 绑可变，右 `$&` = 可写借；可叠加即 A8。否决 `&$`（与 `$&` 对调，破坏 H38 可诊断性）。
3. **类型位**保留 C12 `&T`；可写侧 C13 `$&T`。不把 `T` 重解释成借用。
4. **阶段对齐场景**：
   - **A 诊断**：E22 / E24 / H38；A6 不能写 pointee；误写 `$&*r` / `*$&r` 提示改用 `&*r` 或直接 `r`。
   - **B 降级**：E19/E20 / F26 → “只读写 `r`”；撑起 G29。
   - **C 拼写 + 自动只读借**：A2/A4/A7/A8、C13/C15、D16/D17、F25、G30；E21b 规范 `&*r`；不引入 `$&*r` / `*$&`。
5. **重借用心智**：日常写名字；显式穿过用已有 `&*`；可变标记不堆在重借上。
6. **Non-goals**：D18 不自动借；E21b 不用 `$&r` / `$&*r` / `*$&r`；E23 不升格；H32–H36 不借本次放宽；批准前不实现。

## 1. 问题陈述与源码证据

读代码时，用户需要同时回答四件事：变量能不能重新绑定、引用能不能写、是否正在重借用、父引用何时恢复使用。今天这些概念挤在 `mut`、`&`、`*` 的排列里：

```xu
mut x := 1         // 绑定可变
r := mut &x        // 独占可写借用；r 自己不必是可重新绑定的变量
let s: &int = &*r  // 降为共享借用，同时保留父引用约束
```

痛点的两条主要来源是：通用期望类型位置没有自动 `&mut → &` 降级，必须手写 `&*a`；表达式 `mut &x` 与类型 `&mut T` 顺序相反。前者是能力使用的摩擦，后者是拼写与概念分工的问题，单做 B 不能解决后者。`&*` 也不能简单解释成“取地址和解引用互相抵消”：地址表示可能相同，借用关系却发生了变化。

## 2. 现行语义矩阵

这里的 shared 指“经这条借用途径只读”，exclusive 指“独占可写访问权限”，不等于拥有对象、不等于底层数据永远不变。下表是现行模型；具体 place、可借类型、逃逸与生命周期约束仍适用。

| 位置 / 写法 | 类型或结果 | 读写、别名与转移规则 | 常见误解 |
| --- | --- | --- | --- |
| 类型 `&T` | 共享引用 | 可以复制；允许共享访问，不能经此写入 | `&` 不是普通无限制地址 |
| 类型 `&mut T` | 独占可写引用 | 生命周期内排斥冲突访问；绑定转移通常 move，同步独占参数可 reborrow | 类型里的 `mut` 不修饰绑定 |
| 声明 `mut x := v` | `v` 推导出的类型 | 允许更新绑定；若 `v` 是共享引用，仍不能写 pointee | `mut r := &x` 不会变成 `&mut T` |
| 表达式 `&x`，`x: T` | `&T` | 建立共享借用；变量、字段、受支持元素以及部分字面量 / 临时值有各自路径 | 不是自动降级所有引用 |
| 表达式 `mut &x`，`x: T` | `&mut T` | 要求可写 place，通常要求可变绑定或独占父引用；动态盒类型有现行特例 | 不是声明一个可变绑定 |
| `&r`，`r` 已是引用 | 引用的引用，受支持的嵌套层级内 | 借的是引用槽位，不是 `r` 的 pointee；见 `make_ref_type`、M166 | `&r` 不等于 `&*r` |
| `&*r`，`r: &T` | `&T` | 共享引用复制，保持原 loan 的来源约束 | 无需新增独占权限 |
| `&*r`，`r: &mut T` | `&T` | 共享重借用，父引用冻结直到共享 loan 及后代的最后使用；当前要求 r 为标识符 | 不是消费 r，也不是永久降级 |
| `mut &*r`，`r: &mut T` | `&mut T` | 独占重借用，子 loan 活跃时父引用受冻结约束；当前要求 r 为标识符 | 与共享降级不是一回事 |
| `mut &*r`，`r: &T` | 拒绝 | 不能把共享权限升级为独占权限 | 加 `mut` 不能绕过借用规则 |
| `read(r)`，形参 `&T`、实参 `&mut T` | 通用转换路径当前不匹配 | 通常需 `read(&*r)` | 与已支持的 `r.read()` receiver 路径不同 |
| 无期望类型的 `s := r`，`r: &mut T` | `&mut T` | 绑定转移，按现行 move 规则 | 不会自动猜测需要共享 view |

“冻结”不意味着禁止所有只读 receiver / place 操作；现行 `borrow_walk_receiver` 的共享后代规则仍成立。显式 `&*r` 在被冻结父引用上受更严格检查，这个当前限制要如实记录。

## 3. Goals / Non-goals

Goals：**声明与使用都降低心智负担**——使用者只记三条：① 只读默认、可省略；② 可变绑定 `$name`；③ 可写借用 `$&`。`$` 统一标「可变」，凡可变必有 `$`，只读不出现 `$`；声明标一次即可，使用时不重复标（`$x := 1` 之后写 `x = 2`，不必再写 `$`）。在有明确 `&T` 期望的位置减少显式共享重借用与 `&*`；传参 / receiver 自动只读借。用“访问权限、持有者、最后使用”解释规则；保持编译期内存安全、零 GC、所有权推导和协程边界；减少仅为转换缺失而复制的 `_m` 方法。**否决 `&$` 可变绑定**：它与 `$&` 对调易混，违背降低心智的目标。

Non-goals：

- A / B **不把表达式改写为 `&mut x`**，不改变旧语法；C 的目标拼写已确定为 `$name`（绑定）与 `$&`（借用），不同时引入复合词别名。
- 不关闭或绕过借用检查，不以 C / Go 风格任意可变别名代替现行安全目标。
- 不新增共享到独占的升级，不引入一般子类型关系、容器协变、函数类型协变或多层自动降级。
- B 不从普通 T 自动取引用。C 在明确共享期望下引入受检的自动只读借用（尤其传参 / receiver），不做无期望类型的任意自动借用、自动解引用或任意字段 / 索引重借用，也不补齐整个 MIR 跨 CFG 借用系统。
- 不承诺 719 处全部消失，不把后缀 `_m` 视为可删除证明，不在本文执行批量迁移。

## 5. Phase B 核心：精确的隐式 `&mut T → &T` 规则

### 5.1 转换判定与插入点

设表达式 `e` 的已检查类型为 `got`，上下文期望类型为 `want`。当且仅当 `got` 是 `&mut U`、`want` 是共享 `&U`、两者**直接 pointee 类型相同**且来源可被现有 loan 系统表示时，插入共享重借用。若携带生命周期约束，只能缩短到上下文所需且不超过源 loan 的区域，绝不能扩大。

B 的最小可交付范围要求以下位置一致生效：

1. 同步函数实参，包括普通调用、函数值调用、已有泛型实例化后的实参检查；接入 `check_call_expr`、`check_call_expr_fnval` 与共享的 `coerce_to` 路径。
2. 方法普通参数，以及 receiver 所需的共享访问调整；接入 `check_method_expr`，保留已有方法查找和 receiver 行为，不能只处理参数列表漏掉 receiver。
3. 向已知 `&U` 目标赋值，以及有 `&U` 期望的 `coerce_to` 位置。包括 `check_assign_ident`、字段 / 索引赋值、`check_stmt_let` 的显式类型声明、结构体字段初始化、`check_stmt_return` 的返回期望、受支持的数组元素上下文。每条路径还必须保留各自的存储 / 逃逸检查。

```xu
fn read(v &int) int { << *v }
fn demo(p &mut int) {
    println(read(p))       // B：与 read(&*p) 相同的共享重借用
    let q: &int = p        // B：q 持有共享 loan，父 p 不被 move
    println(*q)
    *p = 2                // q 及其后代最后使用之后才可写
}
```

不向无期望类型的 `q := p` 注入转换；它继续推导成独占引用并遵循 move 规则。**B 不从普通 `T` 自动取 `&T`**；C 的表达式位只读省略另见第 9.4 节，不能声称 B 已实现普通值自动借用。不递归转换 `[]&mut T → []&T`、`&&mut T → &&T`，也不改变嵌套可写引用 pointee 的权限。泛型只在期望已经确定为 `&U` 后执行，不为了让调用成功而猜出新的 U 或改变重载选择。

### 5.2 与 `&*r` 冻结语义等价

对 B 新增的标识符转换 `r: &mut U → &U`，类型结果、owner、投影、parent、持有者及 last-use 约束必须与在该位置手写 `&*r` 等价。不是 move r、复制一个不受追踪的可写指针、全局改写 r 的类型，或用 `same_type` 放行后不记录 loan。

具体不变量：

- 原 local 类型仍为 `&mut U`；转换结果类型为 `&U`，记录一条 shared reborrow，parent 指向原引用，继承所有可能 owner 与投影来源。
- 原引用必须活到转换发生的位置。若结果存入局部、结构体、调用返回值或闭包，loan 延长到该持有者及后代最后使用；不能一律在调用结束时解冻。普通不携带结果的同步只读调用可在调用使用结束后释放，按当前语句粒度保守处理。
- loan 存活时，经父引用的冲突写入、移动、独占重借用仍失败；独占子 loan 存活时也不能隐式产生 shared view。
- 同一表达式的参数按现有求值与临时 loan 规则检查。`f(read_view_of_p, writable_view_of_p)` 不能因第一个参数的类型转换而丢掉冲突；`btmp_*` 目前缺少 parent 维度，实现必须补齐或等价记录临时 reborrow 关系。
- 多来源调用结果继承输入 loan 的保守并集；不能把“返回值只读”误当成“没有借用”。返回局部地址、把短命 loan 塞入长命字段、跨协程或信道传递借用，仍按现有规则拒绝。

**receiver 的现行差异要单独处理。** 已合法的 `r.read()` 使用 `borrow_walk_receiver(..., false)`，允许共享后代共存；B 不对它机械包一层当前更严格的显式 `&*r`，避免现有 `shared_receiver_live_child` 倒退。B 新增的通用转换暂时遵循显式 `&*r` 的冻结检查，包括现有的保守拒绝；不在本阶段顺便放宽所有被冻结父引用上的重复共享重借用。接收者的调整必须记录同等权限和返回值 provenance，不能把 receiver 的只读特例复制成任意参数的豁免。未来统一这两条 shared-view 规则需要独立的安全论证与用例。

### 5.3 `coerce_to` 与表示选择

选择在类型检查期记录“源节点 → 共享重借用调整”，保留原节点 / local 类型与 source span；不在每个后端单独实现规则。可采用专用 adjustment 元数据，或受控的 typed wrapper；本设计要求统一可观察语义，不指定尚不存在的字段名。

所有读取表达式结果类型的地方要看到 adjusted type，所有查询源引用权限的地方要能看到 source type。`arg_pass` 必须接收调整后的共享类型，从而不把父引用记为 move。`borrow_collect_expr`、`borrow_walk_expr`、`borrow_hold_expr`、`borrow_register_ref/field` 都要消费同一调整，注册 shared 而非照搬源引用的 exclusive 位。

在单态化 / 重复检查共享 AST 时，调整不能跨实例污染或重复插入；初始化及 clone 路径也必须覆盖新元数据。仅修改 `ntype[n]` 或只让 `coerce_to` 返回 `want` 是不完整实现：前者会丢源权限，后者会丢 loan。MIR lowering 复用引用值的机器表示，同时保留结果类型与来源信息，保证没有额外分配、复制 pointee、GC 或运行时权限检查。

### 5.4 非标识符来源：B 保留限制

首个 B 对**新增隐式降级**只接受现行显式共享重借用能证明的标识符来源。`consume(a.b)` 中若 `a.b: &mut T`、目标为 `&T`，不能暗中绕过 `&*a.b` 的限制；数组元素或返回独占引用的调用表达式同理。拟报：

```text
cannot implicitly reborrow this &mut reference as shared
note: shared reborrowing currently requires a local reference name
help: bind the reference to a local first, if moving it is allowed
```

手动 `r := a.b; consume(r)` 可能 move 字段、影响后续使用；它不是无语义差异的自动修复。编译器不得偷偷引入这样的 move 临时变量，也不得重复求值有副作用的 receiver。`read(mut &x)` 也不在首个 B 的标识符来源范围内：只读时直接写 `read(&x)`，无需先建立独占借用。已被现有 receiver 路径接受的字段方法调用继续走原来的受检路径，不因这条新转换限制被追溯拒绝。

将隐式路径扩展到任意 place，需要字段 loan 的精确身份、parent 链、单次求值及作用域结束证明，列为后续工作。这样 B 的收益较保守，但不会以隐式语法藏住已有显式限制。

### 5.5 与跨 CFG reborrow 延后的交互

AST 已有 `BorrowState` snapshot / restore / join，以及 `breb`、`bf_reb` 的父链；分支重绑定不能只保留某一路来源。B 必须让隐式 loan 进入同一套数据结构：在 if / match / select 合流取所有可达来源；终止分支不贡献存活 loan；最后使用和作用域约束保持现有保守性。

MIR 的 deferred 注释不授权放松 AST 检查。B 不以 MIR gate 未报错作为别名安全证明，不移除 AST，也不新增跨块借用权限。`bcontrol` 的循环回边引用重绑定拒绝、`bfallback` 的错误回退引用重绑定拒绝继续覆盖隐式路径。若新增上下文无法等价表达显式 `&*r` 的 provenance，应给不支持诊断，不能静默少记一条 loan。

主要风险是“类型转换扩大了实际使用面，暴露原追踪缺口”：调用结果逃逸、同语句多参数、循环、分支父链、嵌套持有者都可能把临时 shared loan 拉长。实现 PR 的准入条件是这些路径的正负例齐全；不要求先完成整个 MIR NLL，但也不允许以 deferred 为理由跳过 B 新增路径的 AST 安全验证。

### 5.6 `_m` 方法处理策略

默认在 B 后另开清理 PR；B PR 保留 `_m` 及其调用，以便语义变化与源码收缩分别回滚。先验证那三个 `Checker` 方法中哪些确实只是只读版重复体、哪些调用已能直接使用只读方法；`direct_type_m` 虽读字段，也要核对与 `direct_type` 的行为等价。

若为了证明 B 必须在同 PR 展示去重，仅选一个等价方法及少量调用作为有测试覆盖的示范，仍在独立提交中。禁止对 23 个 `_m` 声明统一删后缀；其中有 `mir_instr_*_m` 等自由函数和非 `&mut` receiver，后缀本身不是证据。

## 6. 迁移与兼容

旧 `mut x :=`、`mut &x`、`&mut T`、`&*r`（含 `mut &*r`）在 A / B 后仍合法；C 先让它们与 `$x :=`、`$&x`、`$&T` 并存，显式重借继续 `&*r`（可写期望下去掉前导 `mut`），再自动迁移绑定/类型/`mut &`，最后进入旧可变拼写弃用期。最终规范的可变性标记必须有 `$`；兼容期接受旧 `mut` 是显式的迁移例外。`&x` 作为可选只读显式形式保留，逐步弱化，不与旧 `mut` 的强制弃用混为一谈。显式 `&*r` 在无期望类型的 view 中仍有用途，只有等价替代就绪才提示迁移，不先全局禁用。B 不强制格式化器删 `&*`，不改变旧源码解析。

批准后 C 交付自动迁移脚本 / 工具，使用 token / AST / 类型信息，提供 dry-run、逐处 diff、幂等重跑与逆向恢复记录。拼写映射是 `mut name :=` → `$name :=`、`mut &x` → `$&x`、`&mut T` → `$&T`、`mut &*r` → `&*r`（可写由期望 `$&T` 承担；不迁成 `$&*r`）。类型位绝不能机械替成 `&$T`。只读清理另用类型判断：仅当目标已有 `&T` 期望、去掉 `&*` 或 C 中的 `&` 后确实触发等价共享调整且不会改变推导、方法选择、求值或 loan 时才建议。不能用全文 `s/&\*//g`，也不能把 `q := &*r` 直接改成会 move 的 `q := r`；可经类型验证改成 `let q: &T = r`。字符串、编译标签及注释中的普通文本保持原意，内嵌测试程序按独立源码解析迁移，文档示例单独审核。未具备类型信息的脚本只列只读清理候选；`xu fmt` 默认不做语义迁移。

自举顺序必须是“旧语法编译的新编译器先支持 B → 确认 hosted 固定点 → 才清理自举源码”；C 同样先用旧语法实现新拼写的兼容解析及只读调整，更新 hosted seed 并确认 Gen2 == Gen3，再启用工具、逐模块迁移与切换规范输出。每批迁移和最终弃用阶段均重验 Gen2 == Gen3，不让旧 seed 在第一跳遇到未知语法。实测迁移量见第 9.3 节；本次不编写或运行迁移脚本。

针对新增通用路径，成对测试显式 `f(&*p)` 与隐式 `f(p)` 的输出、冲突判定、loan 结束位置；既有 receiver 特例单独测试，不能混作等价对照。测试标量、结构体及切片 / 数组来源，防止只覆盖 `int` 的机器表示。

C 另外验证 `$x :=`、`$&x`、`$&T` 与旧拼写生成相同权限 / loan，以及期望 `$&T` 下的 `&*r` 与旧 `mut &*r` 等价；误写 `$&*r` / `*$&r` / `&$x :=` / 类型 `&$T` 给定向诊断；带 lifetime 类型、函数值 / 匿名函数返回类型、泛型、receiver 与 `let $x: T = ...` 都覆盖。成对验证自动只读 `read(x)` 与 `read(&x)`、`read(r)` 与 `read(&*r)`，以及持有共享结果后的写冲突；无期望绑定的值 / move 推导不变。保留 `$linux`、字符串 `$ident` / `\$` / `$$`、中缀 `&` / `&&` 的回归，验证 fmt 幂等及迁移 dry-run / 幂等 / 内嵌源码处理；规范模式拒绝 `&x :=`、`&$x :=`、类型 `&$T` 等未选/已否决拼写。弃用阶段验证版本 / 模式边界与可操作的迁移提示。

## 8. 风险与回滚

| 风险 | 防范与回滚边界 |
| --- | --- |
| 只放行类型却未建 loan，导致别名写入漏检 | 调整必须被所有借用遍历消费；正负例与显式形式成对。发现漏检就回退 B，保留 A 的解释和诊断。 |
| 父引用被误 move，或冻结太长造成合法程序回归 | 源类型与 adjusted type 分离；检查 `arg_pass`、结果 provenance 和最后使用；保留 receiver 特例。安全但过度保守的情况应清楚诊断，不靠静默强转修复。 |
| 跨 CFG / 同表达式来源丢失 | 合流保留所有 parent / owner，临时 loan 记录 parent；不能把 MIR deferred 当成已实现。 |
| 单态化共享 AST 污染、插入重复 | 调整与实例化作用域一致，覆盖多次检查与 clone 初始化，专门测试多个类型实例。 |
| 自举第一跳不认识新规则 / 新词 | 先发布兼容编译器再迁移源码；保留旧拼写及旧显式 `&*`。 |
| `_m` 或批量清理扩大回滚成本 | 默认单独清理 PR；所有删除均可逆。回滚顺序：先还原依赖 B 的源码清理，再回退 B。 |
| `$` 标签 / 插值被误解释、误写已否决的 `&$`、工具不识别 | C 按声明 / 类型 / 表达式位置解析，保留标签和字符串路径；`&$x :=` 诊断为改用 `$x :=`；先兼容再迁移，不立即删除旧语法。 |

没有生产环境运行时开关可替代这些保证。实现可在开发期以统一编译器开关隔离 B，但若使用，须同时控制类型调整、AST loan 与 MIR 消费，不能只关闭诊断。回滚后的旧源码应仍能显式 `&*` 编译；已迁源码通过独立清理提交还原，不尝试盲目反向替换。

## 9. Alternatives：跳出类指针隐喻

以下保留语义模型与历史候选的对比，便于说明取舍；**最终已选只读默认 + `$` 统一可变标记（第 9.4 节）**。早先的“mut 前加词”及 `mut_ref` / `mut_loan` 偏好已被本次决定覆盖，复合词不再是推荐方向，`~` 重映射已否决。下表的兼容度 / 代码量仍是基于本仓实现的设计评估，非已有语言功能或编译测试结论。

### 9.1 六种语义模型对比

| 方案 | 一句话心智模型 | 与当前借用检查兼容度 | 对自举代码量影响 | 是否仍像指针；诚实取舍 |
| --- | --- | --- | --- | --- |
| ① 保留 `&` / `&mut`，增加 B | “读上下文可从独占引用临时借出只读 view。” | 高；复用现行 shared reborrow、owner / parent / last-use，仍需补齐隐式调整传播 | 不强制改一行使用方；最多减少部分 644 个非 `mut &*` 文本候选和重复 helper，实际量要类型筛选 | 是。风险最小、立即止痛；没有拆开 mut 两义，表达式 / 类型顺序仍不一致。 |
| ② 取消显式重借用符号，全部隐式 reborrow / view | “每个引用使用处按需求授予临时访问权限。” | 中低；要区分无期望绑定的 move / view、独占再借与普通赋值，还要完善表达式顺序、任意 place、CFG provenance | 符号可能最少；理论触及 719 个 `&*` 文本点（含独占），还会改变更多裸引用绑定的含义，不能机械迁移 | 若保留引用类型和 deref，仍有指针外形；若再取消它们则接近 place 模型。简洁表面会隐藏 loan 边界和 move，不适合作为 B 的小补丁。 |
| ③ 单一引用类型，权限在参数 mut / view / loan 注解或 capability 中 | “引用只说明到哪里，权限凭证说明现在能做什么。” | 低；现行 `is_mut_ref_type`、线性转移和 `bexcl` 广泛依赖类型区分，必须把权限带入函数值、泛型、字段、返回值、闭包 | 可缩短类型表面；5,997 个 `&mut` 文本点只是入口，还要迁移权限传播，代码量未必净减少 | 表面可以不像指针，但单一 `ref T` 仍是间接引用；把二分移到注解不等于消灭二分。capability 能更明确，工程与教学成本较高。 |
| ④ 接近 Zig / Go，弱化共享 / 独占二分 | “拿到地址就操作，程序员负责别名与并发纪律。” | 若真取消独占排斥则低，与 Xu 编译期无冲突借用 / 数据竞争防护目标冲突；只换名称则没有消除原问题 | 可能减少权限语法和检查代码，但不能把安全保证损失记作等价精简；不能由 719 次直接估算净收益 | 最像传统指针。Go 的 pointer 类型没有 const/mut 二分；Zig 仍有 `*T` / `*const T`，不能说二者都没有读写区分。Xu 可借鉴简单外形，不应照搬更弱的别名约束。 |
| ⑤ 值语义 / 自动借用，参考 Swift `inout`、自动 ref | “传值负责隔离，需要回写的参数显式标记，编译器自动建立访问区间。” | 中低；调用边界的独占思想可复用，但任意引用字段、逃逸 view、FFI、元素地址和返回借用仍需规则 | 调用处 `&` 可大幅减少；移动、深拷贝 / 写时复制、临时物化或限制逃逸会改变成本模型，前后端及库迁移远大于 B | 日常代码较不像指针，系统接口仍暴露地址。Swift `inout` 不是无限存活的一等引用替代物；Xu 不应以隐式堆分配、运行时 exclusivity 检查或不可预测复制换取外形简洁。 |
| ⑥ 仓内更干净的目标：place + 显式访问角色，值转移单独表达 | “拥有值可以转移；对 place 取得 shared view 或 exclusive loan，绑定 mut 只管重新绑定。” | 概念上高、全面落地中等；对应现有 owner / projection / parent / last-use，但要统一 receiver、显式和隐式 view，扩展到非标识符 place | 先作为术语和 C 的语法糖可零强制迁移；若彻底去掉 `&` / `*` 则需重审引用字段、生命周期和整套编译器，不能承诺靠重命名省代码 | 第一阶段仍像指针，长期可弱化地址隐喻。角色清晰，但安全规则还在；全面语言级重构应另立 spec，不阻塞 B。 |

外部对照依据：[Go 规范的 pointer types](https://go.dev/ref/spec#Pointer_types)、[Go memory model](https://go.dev/ref/mem)（并发写入需要同步），以及 [Zig 官方语言参考](https://ziglang.org/documentation/)（区分可写与 const pointer，允许减弱权限的转换）。由此推断“照搬更弱别名纪律不满足 Xu 当前目标”是本文的设计判断，不是说这些语言没有任何安全机制。

Swift 的对照依据为官方 [Declarations：in-out parameters](https://docs.swift.org/latest/documentation/the-swift-programming-language/declarations/) 与 [Memory Safety](https://docs.swift.org/latest/documentation/the-swift-programming-language/memorysafety/)：回写参数有独占访问区间。上表所列的 Xu 迁移代价是设计推断，不声称 Swift 的所有值传递都产生复制、所有访问都运行时检查，或 Swift 完全采用 Xu 的零 GC / AOT 成本约束。

### 9.2 加词方案：保留备选对比，不推荐

这些方案都不是已选语法，也不作为 C 的并存别名；它们不满足“凡可变必有 `$`”的统一视觉规则。保留它们是为了记录可读性取舍，不再要求在两词中圈选。

| 候选 | 类型位 / 表达式位示意 | 优点 | 不推荐理由 |
| --- | --- | --- | --- |
| `mut_ref` | `mut_ref T` / `mut_ref &x` | “可写引用”较直观，与现有引用类型衔接直接 | 词长且仍须解释独占与 loan；绑定若继续裸 `mut`，仍有两套可变标记，不符合本次决定 |
| `mut_loan` | `mut_loan T` / `mut_loan &x` | 强调借用来源、权限区间及父子 loan | 引入 loan 入门词，作为类型名较生；同样不符合统一 `$` 标记 |
| `ref mut` / `loan mut` / `excl mut` | 如 `loan mut &T` / `loan mut &x` | 可把绑定与借用拆词解释 | 更长，信息重复；`excl` 是缩写，仓内已有同名局部变量 |

保留的 parser 核验结论：`scanner.xu` 的 `lex_ident` 连续扫描字母数字与 `_`，`lookup_keyword` 不含 `mut_ref` / `mut_loan`；本次 `rg -n '\b(mut_ref|mut_loan)\b' src` 无命中。二者当前各是一个普通 Ident，而不是已经支持的新借用关键字。`parse_type` 会走命名类型路径；`mut_ref &x` 在表达式位可能走 `parse_bitand`，按同名变量与 x 的按位与解析。若未来重新评估，仍需解决上下文前缀、同名表达式兼容、lifetime、工具和 seed 问题，不能仅添加关键字。

### 9.4 已拍板：`$name` 绑定 / `$&` 借用，只读默认

#### 硬规则与声明语法

**凡可变必有 `$`；只读不出现 `$`。`$` 是「可变」统一标记。**

心智拆成两层，都要短：

1. **声明**：要不要改这个名字？要 → `$name :=` / `let $name`；不要 → `name :=` / `let name`。
2. **使用（借用）**：要不要改别人的东西？要 → `$&`；不要 → 省略（或兼容期可选 `&`）。

声明标一次即可；之后赋值写 `x = 2`，不必再写 `$`。借用只在需要可写权限时出现 `$&`。此规则约束新规范中引入可变绑定或可写权限的写法：

- **可变绑定 `$name := expr`** 对应今日 `mut name := expr`。声明头只有一个 `$`，不管借用。显式类型写 `let $name: T = expr`；不可变仍写 `let name: T = expr` / `name := expr`。**不要写成 `&$name`。**
- **可写借用表达式 `$&place`、可写引用类型 `$&T`** 分别对应今日 `mut &place`、`&mut T`；两者都是 **`$` 放 `&` 前，即可变标记在前**。显式重借用 `&*r`，对应今日 `mut &*r`，保留 Borrow(Deref(r)) 的结构与现有来源限制。
- **只读借用无 `$`**。有共享期望时默认使用裸表达式，兼容期可显式 `&x` / `&*r`；类型位建议保留 `&T`。`$s` 若保存共享引用，其中 `$` 只标 s 的绑定可变，s 的类型仍是 `&T`，不能据此写 pointee。
- 不接受裸 `&x :=`、`&$x :=` 作为可变声明（`&$` 已否决），也不接受类型 `&$T`、通用 `$T`（无 `&`）的模糊新含义；规范可变绑定就是 `$name`；不引入第二种等价规范拼写。`$` 本身是统一标记，不是单独的取引用、转移或权限升级操作。

“凡可变必有 `$`”不要求每次读取或赋值都重写 `$`：`$x := 1` 之后仍用 `x = 2`，`r: $&T` 之后仍用 `*r = ...`。标记在绑定声明、权限类型或显式取得可写借用处可见；已有的同步独占参数重借用规则不因此改变，也不新增“从普通 T 自动取得可写借用”。编译标签 `$linux` 与字符串插值 `$name` 属于既有非权限语法，保留原意，不纳入只读 / 可变标记规则。

#### Readonly marking

| 方案 | 类型位 / 表达式位 | 别名可见性 | 与隐式 `&mut → &` 的关系 | 自举噪声利弊与决定 |
| --- | --- | --- | --- | --- |
| (1) 显式标注 | `&T`；读调用总写 `read(&x)`，共享重借用写 `read(&*r)` | 调用点肉眼可见借用动作，仍看不出完整 loan 区间 | 若每次仍要求显式，只发挥不了 B 省略 `&*` 的主要收益 | diff 小，但高频只读路径持续有符号噪声；**未选** |
| **(2) 只读默认可省略** | 读调用 / receiver 默认 `read(x)` / `x.read()`；类型位是否保留引用形状由下面建议明确 | 调用点不再显式标每条共享别名；签名、类型、IDE loan 提示及诊断必须可见来源 / 最后使用 | **已选策略**；B 的可写引用 → 只读 view 是其语义基础，C 再补普通 place 的自动只读借用 | 把日常噪声集中在可变路径，减少自举读调用的符号；代价是读者更依赖签名和工具，清理必须经类型验证 |
| (3) 类型位保留、表达式位可省略 | 固定保留 `&T`，在明确共享期望下省略表达式 `&` | 签名仍显式区分拥有值 / 借用，调用点别名动作较隐含 | 可直接承载 B；普通 T 自动借用仍需 C 的独立调整 | 工程边界较保守，类型位符号仍多；**未另选为独立策略**，其类型保留方式作为 (2) 的落地建议 |

**已选 (2)。建议类型位仍需 `&T`，本 spec 按此形式定义矩阵和迁移目标。** “只读默认”省的是只读权限的额外标注及表达式位借用动作，不把 `T` 偷偷重解释成 `&T`：`T` 继续表示值 / 所有权，`&T` 表示共享引用，`$&T` 表示独占可写引用。因此 (2) 与 (3) 在这版建议的表面语法上有交集，但本次拍板的是“可变才标”的总体策略，不是只允许删除少数表达式符号。完全删除类型位 `&` 会改变拥有 / 借用区分、泛型和字段语义，须另立 spec，当前不推荐。

表达式省略必须由上下文确定，不能靠“多数时候只读”猜类型或改变 move：

1. **B 先交付引用降级**：`r: &mut T`（C 后为 `$&T`）在 `&T` 期望下写 `read(r)` 或 `let s: &T = r`，产生 shared reborrow，冻结父 loan 到 s 及后代最后使用。旧显式 `&*r` 的权限、来源限制、receiver 例外与第 5 节保持一致。
2. **C 补自动只读借用**：已知形参为 `&T` 时，普通可借 place x 可写 `read(x)`，receiver 按只读签名自动借；显式共享目标如 `let s: &T = x` 同样可省略表达式 `&`。目标明确、直接 pointee 类型相同、来源可表示且生命周期合法时，插入与 `&x` 等价的 shared borrow；保存 / 返回结果时不能一律在调用结束释放。只读自动借用不得用于解决未知泛型 / 重载选择，也不放宽第 5.4 节任意字段 / 索引重借用的边界；不能表示的来源给诊断。
3. 无共享期望的 `s := x` 继续按值推导，`q := r` 继续按 r 的引用类型推导并遵循原 move 规则。要在这种位置保留共享 view，可写 `let s: &T = x` / `let q: &T = r`；兼容的 `s := &x` / `q := &*r` 仍是显式逃生口。`&r` 借引用槽位，`&*r` 借 pointee，二者不合并；可写显式重借用仍是 `&*r`（期望 `$&T`），不能因 B 改成含义不同的 `$&r`，也不引入 `$&*r` / `*$&r`。

`&x` 的逐步弱化建议：并存期先接受、无默认警告；文档 / 新示例优先裸只读调用；自动迁移工具在等价上下文提供可选清理；工具与 seed 稳定后再提供可选 style 提示。**不为了弱化显式只读而立即禁用 `&x`，也不在尚无等价替代的地方删除 `&*r`**。fmt 只规范空格，不擅自移除会影响推导 / alias 的符号。

隐藏借用动作减少自举噪声，同时降低局部代码的别名可见性；用函数签名 `&T`、编辑器显示的 inferred / adjusted type、隐式 loan 的源位置与 last-use note 弥补。诊断须说明“为只读参数 / receiver 自动借用”，发生冲突时指向实际源码，不能显示用户未写过的 `&*`。所有约束仍在编译期检查，无 GC、无运行时借用对象。

#### 定稿矩阵（与 §0 场景对齐）

以下是目标规范，**当前编译器尚未支持这些新拼写**；行与 §0 的 A1–E21 / F26 对应。只读裸表达式须有共享期望；“有无 `$`”描述新写法中被声明 / 取得的可变性，旧兼容例外见第 6 节。每行是独立示例，不在一个作用域同时建立互相冲突的 loan。

| 意图 | 今日写法 | 新写法 | 有无 `$` |
| --- | --- | --- | --- |
| 不可重绑值 | `x := v` | `x := v` | 无 |
| 可变绑定，推导类型 | `mut x := v` | **`$x := v`** | 有，绑定 |
| 可变绑定，显式类型 | `mut x := v`（今日此声明头无显式类型槽） | `let $x: T = v` | 有，绑定；C 新增类型槽 |
| 只读引用类型 | `&T` | **`&T`**，建议继续必写引用形状 | 无 |
| 只读参数 / receiver | `read(&x)` / `x.read()` | **`read(x)` / `x.read()`**；`read(&x)` 兼容可选 | 无 |
| 普通 place 的共享持有者 | `let s: &T = &x` | `let s: &T = x`；`s := &x` 兼容可选 | 无 |
| 可写借用表达式 | `mut &x` | **`$&x`** | 有，借用 |
| 可写引用类型 / receiver | `&mut T` / `fn (r &mut T) write()` | **`$&T`** / `fn (r $&T) write()` | 有，类型权限 |
| 可重绑的共享引用绑定 | `mut s := &x` | `let $s: &T = x`（也可 `$s := &x`） | 有，只有绑定可变；共享权限无 `$` |
| 不可重绑、可写 pointee | `r := mut &x` | `r := $&x` | 有，只有借用可写 |
| 可重绑、可写 pointee | `mut r := mut &x` | **`$r := $&x`** | 两处，分别标绑定与借用 |
| 只读重借（共享复制或独占降级） | `read(&*r)` / `s := &*r` | **`read(r)`** / `let s: &T = r`（B）；`&*r` 兼容 | 无；日常省略 |
| 可写重借：同步传参 | 自动 / 偶发手写 | **`f(r)`**（E21a） | 调用点常省略 |
| 可写重借：显式独占子 loan | `mut &*r` | **`&*r`**（E21b，期望 `$&T`；否决 `$&*r` / `*$&r`） | 复用 `&*`；权限来自期望 |
| 无期望的独占引用转移 | `q := r`，r 的类型为 `&mut T` | `q := r`，r 的类型为 `$&T` | 此使用处无；仍是 move，不是重借 |

#### 正交性、顺序风险与诊断 / fmt

心智模型压成三句 + 重借一句：**只读默认可省；可变绑定 `$name`；可写借用 `$&`；显式重借用已有的 `&*`。** `$` 只答“是否可变”（绑定 / 从 place 取可写借 / 类型）；重借不堆 `$&*` / `*$&`。绑定与 pointee 可写正交：`$s := &x` 不能写 pointee；`r := $&x` 不自动可重绑；需要时 `$r := $&x`。

声明标一次、使用不重标。只读写 `read(x)` / `read(r)`。拥有值可写借 `$&x`；已有引用再借 → `r` 或 `&*r`。误写 `$&*r` / `*$&r` 一律指向 `&*r` 或 `r`。

旧稿曾用 `&$name :=` 标可变绑定，与 `$&` 仅次序相反、极易写混，**已否决**。现规范里绑定没有 `&`，借用才有 `&`，字形分工即降低心智。缓解 / 防退回旧稿的措施：

- parser 按位置诊断：`$&x := v` 提示 `mutable binding declarations use '$x :='`；误写 `&$x :=` / 表达式 `&$x` 提示 `rejected spelling; use '$x :=' for mutable binding, '$&x' for writable borrow`；类型 `&$T` 提示 `writable reference types use '$&T'`；误写 `$&*r` / `*$&r` 提示 `explicit reborrow uses '&*r' (or just 'r' under expectation)`；`$&r` 当 pointee 重借时说明借槽 vs `&*r`。不得静默改写。
- fmt 统一 `$x := v`、`$&x`、`$&T`；重借保持 `&*r`；不输出 `$&*r` / `*$&r`。
- 入门文档用一张三行表教完：只读可省 / `$name :=` / `$&`；并排一例 `$r := $&x` 说明左绑定、右借用。

**与 B 正交**：B 改的是 `&mut T → &T` 的受检调整，C 后写作 `$&T → &T`；C 改可变性拼写并补普通 place 的只读省略。B 可先用旧语法独立交付，新旧拼写走同一 owner / parent / last-use / provenance 规则；换符号本身不产生降级。B 不自动抹掉无期望的独占重借用，也不升级共享权限。receiver 既有的共享后代特例仍单独处理，不能把普通值自动借用混写成 B 已有能力。

#### lexer / parser 可行性：源码核验与待实现边界

本次实际执行的主要 `rg` 检查如下；这是源码静态核验，不是新语法已编译通过的声明：

```sh
rg -n -F '$' src/xu/scanner/scanner.xu src/xu/parser/parser.xu
rg -n 'TOK_DOLLAR|TOK_AMP|TOK_MUT' src/xu/ast/kind.xu
rg -n 'c == 36|c == 38|c == 126|unexpected character' src/xu/scanner/scanner.xu
rg -n 'parse_stmt|k == 5|kind_at' src/xu/parser/statements.xu
rg -n 'parse_type|is_type_start_at|kind_at|NT_REF' src/xu/parser/declarations.xu
rg -n 'parse_unary|parse_bitand|Optional return' src/xu/parser/expressions.xu
rg -n 'Dollar|Amp|tk == 90' src/xu/printer/printer.xu
rg -n '^\$' src
rg -n -F '$&' src
rg -n -F '&$' src
```

- **lexer 可以复用现有 token，未发现这两种新组合的已用语法。** `ast/kind.xu:46,97` 分别定义 `TOK_AMP = 39`、`TOK_DOLLAR = 90`；`scanner.xu:979,1023` 将单 `&`、`$` 各自分词。因此 `$x :=` 可分成 Dollar / Ident / ColonAssign，`$&x` 分成 Dollar / Amp / Ident，不需要把组合强制合成新 token；`&&` 仍按最长匹配保留。旧稿 `&$x :=`（Amp+Dollar）已否决，见下条诊断。`rg -F '$&' src` 只有 `src/net/url/mod.xu:663` 的 URL 字符注释，`rg -F '&$' src` 无命中，不能据此保证仓外无用例。
- **`$x :=` 的 parser 可行，但当前不支持。** `statements.xu:82` 的 `parse_stmt` 在通用表达式之前已有 `mut` 声明分支（`NK_LET.ival = 1`）与 Ident / `:=` 前瞻分支；可在此前用 **Dollar / Ident / `:=` 三 token** 声明头前瞻识别，生成同样的 mutable Let。`let $x: T = v` 则在现有 `let` 分支、`expect_ident` 之前读取可选 `$`，记录同一标记。**关键：`$` 只在语句头的 `$ Ident :=` 与 `let $ident` 处识别为可变绑定**，与编译标签 `$linux`、字符串插值 `$name` 隔离。误写 `&$x :=` 必须诊断为改用 `$x :=`，不得静默接受；`$&x :=` 不得落入泛化赋值错误。现有通用表达式不接受 Dollar 前缀作绑定，所以这是新增合法语法。
- **借用两侧统一 `$&`。** `expressions.xu:191` 的 `parse_unary` 目前只识别 `mut` + Amp 生成 `NK_BORROW.ival = 1`；C 在同一层新增 Dollar + Amp 识别 `$&place`；显式重借继续走 `&*`（可写期望下即独占；迁移去掉 `mut &*` 的 `mut`），不新增 `$&*` / `*$&`。`declarations.xu:467` 的 `parse_type` 新增 Dollar + Amp，生成 `NT_REF.ival = 1`，复用现有引用 pointee / lifetime 解析；并存期保留旧 Amp + `mut` 分支。不能先建立共享借用再“升级”。
- **所有类型入口都要同步。** `is_type_start_at`、普通 / 匿名函数和函数类型的可选返回类型判断、泛型实参、receiver、结构字段与 lifetime lookahead 都要接受 Dollar + Amp；只改 `parse_type` 不够。现有 `&a T` 不变，旧 `&mut a T` 的新写法是 `$&a T`；不把 lifetime 名当作 `$` 的修饰对象。现有嵌套引用限制继续由类型检查执行。
- **`$` 有现有用途，必须按位置隔离。** `parser.xu:800` 起在包声明后、imports / declarations 前读编译标签；源码中确有 `$linux`、`$windows`、`$x64` 等。`parser.xu:639` 起处理普通字符串中的 `$ident`、`\$` 与 `$$`；它们走独立字符串路径。新增前缀仅在相应声明 / 类型 / unary 上下文识别，不把 `$word` 全局改为可变性标记，不用全文替换；文件头 Dollar 仍要求合法标签。
- **保留其它 `&` 语义并更新工具。** `parse_bitand` 的中缀 `a & b`、`&&`、只读类型 `&T`、兼容表达式 `&x` 都不重定义。`printer.xu` 的 `fmt_space` 已有 Amp / Dollar 紧贴规则，token 90 已可打印，但这不证明组合格式和词前空格正确；C 必须补上下文格式测试、LSP、高亮、doc、诊断及迁移工具，再切换规范输出。

**已否决的 `~` 方案（历史说明）**：不采用 `~T` / `~x` / `~*r`，也不采用不含 `$` 的可变绑定 `&x :=`。理由是可写路径缺少统一 `$`，需要额外记忆独立权限符号；`~` 还需新增 token 与全套工具支持。核验表明当前 lexer 没有字节 126 分支，`~` 不是 Xu 已有按位取反运算符；否决理由不是与现有 `~` 运算冲突。不再为它保留未决的只读标记或平行迁移路线。

## 10. 实现顺序（按 §0 场景）

1. **批准本 spec**：确认 §0 场景表、来源边界、G31 receiver 特例、C12 类型位 `&T`、兼容与验收；批准前只改本文，不写实现。
2. **Phase A：诊断**（E22 / E24 / H38，A6 不能写 pointee）。补齐借用诊断与文档入口；不改变合法程序集合；Gen2 == Gen3。
3. **Phase B：隐式 `&mut T → &T` 降级**（E20 / F26，并支撑 G29）。统一 adjustment 与 loan 传播；保持 E24 标识符限制与 G31；尚不含 D16/F25 普通 T 自动借；Gen2 == Gen3。
4. **Phase C：新拼写并存 + 自动迁移**（A2/A4/A7/A8、C13/C15、D16/D17、F25、G30；E21b=`&*r`）。兼容解析 `$name` / `$&`；不引入 `$&*r` / `*$&`；E19–E21a 以省略为主；每批 Gen2 == Gen3。
5. **旧拼写弃用**。`mut` / `mut &` / `&mut` 进入提示与兼容退出；`&*` 仅在已有等价只读替代处提示；`&x` 兼容期可选；Gen2 == Gen3。不在本文承诺删除日期。

B 后的 `_m` 去重、类型验证后的 `&*` 清理仍可独立进行，逐项证明等价、保留可回滚改动；它们不替代 C。以上每个阶段都要求第 7 节中与变更相符的检查，不能因 make 返回成功而省略严格固定点证据。

## 11. Future work：更完整的 view 模型

## 12. Recommendation

以 **§0 场景全表** 为规划前提，执行 **Phase A 诊断 → Phase B 隐式 `&mut T → &T` 降级 → Phase C 新拼写 `$name` / `$&` 并存 + 自动迁移 → 旧拼写弃用**。心智三句覆盖全部场景：只读可省；`$name` 可变绑定；`$&` 可写借用；声明标一次、使用不重标。C 的规范是可变绑定 `$x := ...`、可写借用 `$&x` / `$&T`；显式重借用 `&*r`；只读表达式默认省略。建议类型位继续保留 `&T`。旧稿 `&$` 绑定已否决。

符号噪声集中在可变路径：`$` 统一标可变，只读无 `$`；绑定用 `$name`、借用用 `$&`，二者字形不同，避免 `&$`/`$&` 对调；误写 `&$` 由诊断直接指回 `$name :=`。`mut_ref` / `mut_loan` 仅备选且不推荐，`~` 已否决。B 的 loan / parent / last-use / provenance、安全边界与既有 receiver 特例不因新拼写改变。

**每阶段 Gen2 == Gen3 必过；批准 spec 前不实现。** 先交付旧 seed 可编译的兼容编译器，再更新 seed、迁移源码，最后弃用旧拼写；本次仅定稿此文档，不修改编译器、不执行迁移或自举构建。
