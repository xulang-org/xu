## ⚡ Xu с первого взгляда (Показываем на деле)

Никакого громоздкого шаблонного кода. Никакой акробатики с явными аннотациями времён жизни. Оцените чистый современный синтаксис Xu в 15 строках:

```xu
@main
#errors

// Символьный поток управления: `<<` возвращает значение, `>>` выбрасывает ошибку; без вложенных Result/unwrap
fn fetch_metric(task string) int {
    if task.len == 0 { >> errors.new("empty task name") }
    << task.len * 42
}

fn worker(task string, ch chan int) {
    val := fetch_metric(task) or (err) { << } // Обязательная локальная обработка без `if err != nil`
    ch <- val                                 // Типобезопасный обмен сообщениями через каналы
}

fn main() int {
    ch := chan int{cap: 2}
    xu worker("latency", ch) // Нативное ключевое слово `xu` запускает легковесную корутину
    xu worker("memory", ch)
    println(<-ch + <-ch)     // Агрегация fan-in из каналов
    << 0                     // Детерминированное освобождение, ноль пауз GC, статическая AOT-компиляция
}
```

> **За что разработчики ценят Xu**:
> 1. **Символьный поток управления**: `<<` — возврат, `>>` — ошибка, `<<<` — выход. Прощайте многословные устаревшие ключевые слова.
> 2. **Эргономичная обработка ошибок**: Обрабатывается в месте вызова через `or (err) { ... }`. Избавляет от загромождающих экран `if err != nil` и внезапных паник `unwrap()` в рантайме.
> 3. **Нативная легковесная конкурентность**: Корутины `xu worker()` + каналы `chan` дают простоту конкурентности в духе Go.
> 4. **Статическая безопасность при компиляции**: Вывод владения и заимствований. **Без сборщика мусора (Zero-GC)**, без пауз и с предельно компактным детерминированным потреблением памяти.

Изменяемая ссылка с именем `r: $&T` может удовлетворять ожиданию `&T`: пишите `read(r)` или `let view: &T = r`. Разделяемое представление замораживает родительский объект от конфликтующих записей и перемещений вплоть до последнего использования, включая сохранённые представления и результаты вызовов. Конфликтующие разделяемые и изменяемые аргументы в одном вызове отклоняются. Неявное понижение сейчас требует локального имени ссылки и идентичного прямого целевого типа. Объявляйте изменяемую переменную один раз через `$x := value` (или `let $x: T = value`), а далее используйте обычное имя `x`. Обычным значениям требуется `&x` для разделяемого заимствования или `$&x` для изменяемого заимствования (тип ссылки `$&T`). Повторно используйте имена ссылок как `r` или пишите `&*r` для явного перезаимствования. Автоматическое заимствование от обычных значений не реализовано.
Низкоуровневые аппаратные и bare-metal контракты: ядра ОС и драйверы устройств работают через сырые указатели `*raw T`, разыменование которых требует явных блоков `unsafe { ... }` (например, `p := addr as *raw u32; unsafe { *p = val }`), полностью обходя вывод заимствований; MMIO использует встроенные барьеры `volatile_read` / `volatile_write`; разметка структур поддерживает выравнивание `@repr("C", align: N)` и плотную упаковку без выравнивающих байтов `@repr("C", packed)`; bare-metal исходники указывают `$freestanding`, полностью отключая системные вызовы хоста и libc.

Актуальные правила см. в [Руководстве по заимствованию и модели памяти](https://xulang.org/ru/docs/lang/memory/).

## 🎯 Проблемы индустрии и «Почему Xu?»

При создании высокопроизводительных систем и сервисов инженеры постоянно вынуждены выбирать между несовершенными компромиссами:

### 1. Дилеммы, которые мы решаем

- **Проблема 1: Скачки задержек сборщика мусора и раздувание памяти**
  - *Сейчас*: Go и Java продуктивны, но паузы GC (STW) и непредсказуемый джиттер задержек критичны для шлюзов с низкой задержкой, торговых движков и встраиваемых систем.
  - *Решение Xu*: **Рантайм без GC (Zero-GC)**. Чистая AOT-компиляция. Владение отслеживает память при компиляции и детерминированно освобождает её при выходе из области видимости. Ноль пауз и скачков GC.
- **Проблема 2: Борьба с «адом явных аннотаций времён жизни»**
  - *Сейчас*: C/C++ подвержен висячим указателям, порче памяти и уязвимостям UAF. Rust безопасен, но явные параметры времён жизни (`'a`, `'b`) и сложная гимнастика типов резко замедляют разработку.
  - *Решение Xu*: **Неявный вывод владения и проверка заимствований**. В прикладном коде не нужны явные аннотации lifetime. Естественная семантика значений для срезов сочетает безопасность и скорость разработки.
- **Проблема 3: Заполняющий экран шаблонный код и многослойные обёртки ошибок**
  - *Сейчас*: Код на Go переполнен повторяющимися `if err != nil`. Rust оборачивает типы во множество слоёв `Result<T, E>` / `Option`.
  - *Решение Xu*: **Символ `>>` в паре с обязательным `or (err) { ... }`** обеспечивает лёгкое, чистое и безопасное распространение ошибок.
- **Проблема 4: Фрагментированный инструментарий и сложность настройки**
  - *Сейчас*: Связка из CMake, Make, пакетных менеджеров и платформенных линкеров печально известна своей хрупкостью.
  - *Решение Xu*: **Замкнутый цикл в одном бинарнике**. Всё — компилятор, раннер тестов, форматтер (`xu fmt`), генератор документации (`xu doc`) и собственные графические мастера установки — встроено из коробки.

### 2. Прямое техническое сравнение

| Ключевой параметр | C / C++ | Go | Rust | **Xu** |
| :--- | :--- | :--- | :--- | :--- |
| **Управление памятью** | Ручное `malloc`/`free`<br>*(Утечки и висячие указатели)* | Сборщик мусора (GC)<br>*(Паузы STW и раздувание памяти)* | Владение при компиляции<br>*(Явные аннотации `'a`)* | **Владение при компиляции<br>(Zero-GC / Детерминированный сброс)** |
| **Накладные расходы** | Абстракции с нулевой ценой | Высокие (движок GC + планировщик) | Абстракции с нулевой ценой | **Нулевые (Без GC / Чистый нативный машинный код)** |
| **Когнитивная нагрузка** | Уязвимость к UB и гонкам | Просто, но остаются паники `nil` | Крутая кривая (борьба с borrow checker) | **Минимальная (Без аннотаций lifetime / Чистый поток)** |
| **Модель конкурентности** | Потоки ОС / Внешние библиотеки | Корутины CSP (`go`) + каналы (`chan`) | Потоки / Async-рантаймы (окраска функций) | **Нативные легковесные корутины (`xu`) + типизированные `chan`** |
| **Обработка ошибок** | Коды ошибок / Исключения *(Неявно)* | `if err != nil` *(Громоздкий шаблон)* | `Result<T, E>` + оператор `?` | **Символьный поток: `>>` ошибка + обязательный `or`** |
| **Поток управления** | `return` / `break` / `continue` | `return` / `break` / `continue` | `return` / Хвостовые выражения | **Символьный поток: `<<` возврат / `>>` ошибка / `<-` выход** |
| **Целостность инструментов** | Фрагментирован (CMake/Make/Conan) | Интегрирован из коробки | Интегрирован (Cargo) | **Единый бинарник (build/test/fmt/doc встроены)** |
| **Кроссплатформенная установка** | Сложные зависимости тулчейна и линкера | Официальный установщик / ручной PATH | Нужен rustup и внешние сетевые скрипты | **Автономные GUI-мастера / Установка в один клик** |
| **Bare-metal и ядра ОС** | Ручная линковка и inline asm, небезопасно | Не поддерживается (привязка к GC/рантайму) | Поддерживается (`no_std`), тяжёлые lifetime | **Нативная поддержка (`freestanding` / `#core`)<br>Zero-GC детерминированный сброс + Вывод времён жизни** |

## 🚀 Быстрый старт без барьеров

### Вариант 1: Мгновенная песочница в браузере (Без установки)

Переходите сразу в **[Онлайн-песочницу xulang.org](https://xulang.org/ru/playground/)**. Клиентская WebAssembly-песочница поддерживает подмножество Xu: базовые типы, управление потоком, структуры, диагностику заимствований и кооперативное планирование каналов. Подробности охвата см. в руководстве песочницы; настоящая многопоточность, сетевой ввод-вывод, нативный C FFI и десктопный UI требуют нативного SDK.

### Вариант 2: Быстрая установка одной командой (Рекомендуется)

Xu поставляется в виде автономных установщиков со встроенным компилятором и исходниками стандартной библиотеки, которые автоматически настраивают системные переменные окружения:

- **macOS / Linux** (одна команда в терминале):
  ```bash
  # Автоматически определяет архитектуру, скачивает и настраивает окружение
  curl -fsSL https://xulang.org/install.sh | bash
  ```
  *Или скачайте автономные бинарники из [Releases](https://github.com/xulang-org/xu/releases):*
  ```bash
  chmod +x xu-setup-linux-x64 && ./xu-setup-linux-x64 -y
  ```

- **Windows** (GUI-мастер или PowerShell):
  - **GUI-мастер**: Скачайте `xu-setup-windows-x64.exe` из [Releases](https://github.com/xulang-org/xu/releases) и запустите двойным щелчком автономный графический мастер без зависимостей.
  - **Консольный установщик ARM64**: Скачайте `xu-setup-windows-arm64.exe` из [Releases](https://github.com/xulang-org/xu/releases) и выполните `.\xu-setup-windows-arm64.exe --yes` в PowerShell.
  - Установщики SDK настроены на запуск от текущего пользователя из обычного терминала. Установка для всех пользователей по-прежнему требует прав администратора.
  - **Одна команда в PowerShell**:
    ```powershell
    irm https://xulang.org/install.ps1 | iex
    ```

> Откройте новый терминал и введите `xu --version` для запуска из любой директории.

### Вариант 3: Hello World за 30 секунд

```bash
# 1. Создайте исходный файл
cat << 'EOF' > main.xu
@main

fn main() int {
    println("Hello, World! Welcome to Xu.")
    << 0
}
EOF

# 2. Запустите сразу
xu run main.xu

# 3. Скомпилируйте AOT в оптимизированный нативный бинарник
xu build main.xu -o myapp
./myapp
```

## 🖥️ Разработка ядер ОС и Bare-Metal

Xu нативно поддерживает **ядра операционных систем, встроенные прошивки и bare-metal драйверы**. Благодаря строго изолированной многослойной архитектуре Xu сохраняет **детерминированное освобождение без GC** и **неявный вывод владения (без ручных аннотаций lifetime)** в обычном коде, изолируя работу с аппаратурой в нижних 5 % кодовой базы:

* **Автономный режим Freestanding**:
  * Исходная директива `$freestanding`, манифест проекта `xu.xun` (`profile: freestanding`) или флаги CLI `--profile=freestanding` / `--no-std` полностью отключают зависимости от системных вызовов ОС хоста, планировщика рантайма и libc.
* **Строго изолированные аппаратные контракты**:
  * **Сырые указатели (`*raw T`)**: Разыменование требует явного блока `unsafe { ... }`; вывод владения и заимствований полностью обходит сырые указатели, не создавая трения для обычного прикладного кода;
  * **Volatile MMIO-барьеры**: Встроенные примитивы `volatile_read` и `volatile_write` предотвращают удаление мёртвого кода (DCE) и вынос инвариантов цикла (LICM);
  * **Точный контроль разметки памяти**: `@repr("C", align: 4096)` для таблиц страниц с выравниванием 4 КБ (PML4 / Page Directory) и `@repr("C", packed)` для аппаратных сетевых пакетов и дескрипторов без выравнивания.
* **Чисто статическая базовая подсистема (`#core`)**:
  * `#core/arch`: Привилегированные инструкции CPU (`cli`, `sti`, `hlt`, `pause`, `wfi`), доступ к управляющим регистрам (`read_cr2/cr3`, `write_cr3`, `invlpg`, `set_vbar`, `set_trap_vector`), дескрипторы шлюзов прерываний IDT (`load_idt`), переназначение PIC 8259A (`pic_remap`) и инициализация таймера PIT 8254;
  * `#core/sync`: Безопасные при прерываниях спинлоки `IrqSpinlock` и `Spinlock` с RAII-охранниками `IrqGuard` и `SpinGuard` для **детерминированного снятия блокировки без GC и восстановления прерываний при выходе из области видимости**;
  * `#core/task`: Кросс-архитектурный 192-байтовый `TaskContext` с 16-байтным выравниванием, атомарное переключение контекста (`switch_context`), полные снимки регистров при ловушках (`TrapFrame`) и точки входа системных вызовов (`syscall_entry`);
  * `#core/virtio`: Чисто статический фреймворк драйверов VirtIO MMIO, кольца дескрипторов VirtQueue, `VirtioBlkDriver` (блочное дисковое устройство) и `VirtioNetDriver` (виртуальная сетевая карта);
  * `#core/mem` и `#core/alloc`: Встроенные функции памяти без аллокаций (`memset`/`memcpy`/`memcmp`) и подключаемый контракт аллокатора (`GlobalAlloc`).
* **Мгновенная генерация каркаса ядра**:
  ```bash
  # Инициализация нового bare-metal проекта ядра (создаёт xu.xun, main.xu, linker.ld и мультиархитектурный Makefile)
  xu init --baremetal my_os
  cd my_os

  # Сборка компактных ELF-образов bare-metal ядра под разные архитектуры (~1,9 КБ – 2,4 КБ)
  make
  # Или прямой запуск в эмуляторе QEMU
  make qemu
  ```

- [x] **Символьный поток и обработка ошибок**: Возврат `<<`, выброс `>>` и обязательные локальные обработчики `or (err) { ... }`
- [x] **Кроссплатформенная кодогенерация**: Windows / macOS / Linux, ARM64 / x64 / LoongArch64 / RISC-V, WASM и bare-metal цели
- [x] **Поддержка ядер ОС и bare-metal**: Профиль freestanding, чисто статическая подсистема `#core` (arch/mem/sync/task/alloc/virtio), спинлоки с защитой от прерываний, атомарное переключение контекста, фреймворк драйверов VirtIO и генератор каркаса (`xu init --baremetal`)
- [x] **Установка и самообновление SDK**: Мастер Windows, macOS PKG, однофайловый кроссплатформенный Setup и `xu up/update`
- [x] **Воспроизводимые зависимости модулей**: `init/get/install`, MVS, lock-файлы/vendor, прокси, офлайн/замороженные сборки и клиент проверки контрольных сумм с доверенным ключом
- [x] **LSP и интеграция с редакторами**: `xu-lsp` и расширения VS Code/Cursor; диагностика, автодополнение, переход к определению, подсказки, символы, ссылки, переименование и форматирование
- [x] **Обобщения (Generics) и база SSA-оптимизаций**: Мономорфизация без ограничения на 4 параметра типа, скалярное продвижение SSA, ядра циклов ARM64 SSA и вращение циклов
- [x] **Диагностика и верификация компилятора**: Пошаговая верификация MIR, дампы MIR, счётчики совпадений шаблонов и именованные переключатели оптимизаций
- [x] **Инфраструктурные пакеты**: Отдельный модуль packages предоставляет 29 расширений, включая MySQL, Postgres, Redis, ClickHouse, Kafka и SQLite
- [x] **Воспроизводимые кросс-языковые бенчмарки**: 72 нагрузки на шести платформах ARM64/x86-64 с фиксацией измеренных версий компиляторов, происхождения и проверкой вывода
- [x] **Встроенный интерактивный отладчик исходного кода**: `xu debug` управляет DWARF-точками останова, стеками вызовов и типизированным просмотром локальных переменных через LLDB/GDB с неинтерактивным пакетным режимом
- [x] **Дальнейшее расширение оптимизатора**: Глубокое скалярное SSA-продвижение с доказательствами допуска записей структур, планирование тайлинга в духе TVM, низкобитный LUT-GEMM и конвейерное слияние операторов
- [ ] **Полная рантайм-валидация на целевых машинах**: Шлюзы установки нативного SDK охватывают macOS ARM64/x64, Linux ARM64/x64 и Windows x64/ARM64. Расширение проверок библиотек, сети, конкурентности и десктопного UI на каждой цели; SDK для LoongArch64 и RISC-V собираются кросс-компиляцией.
- [ ] **Публичная инфраструктура пакетов**: Проверка контрольных сумм с доверенным ключом, MVS и клиенты proxy/vendor реализованы. Публичные сервисы proxy/checksum и независимые свидетели требуют отдельного развёртывания и проверки доступности.
